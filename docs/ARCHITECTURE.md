# 설계 문서

회의·면담을 녹음해 기기에서 받아쓰고, AI로 결정 사항과 할 일을 정리해 iOS 미리알림까지 이어 주는 iOS 앱.
지난 회의는 질문 탭에서 대화하듯 물어보고, 답의 근거가 된 발언으로 바로 이동할 수 있다.

최종 갱신: 2026-11-10 (5단계 + 질문 탭 완료 시점)

## 전체 구조

```
┌──────────────────────────── iPhone (iOS 26) ─────────────────────────────┐
│                                                                           │
│  마이크 ─▶ AVAudioEngine ─▶ AudioPipeline ─┬─▶ SpeechAnalyzer (기기 내 인식) │
│                              (형식 변환)    ├─▶ m4a 파일 (기기에만 저장)      │
│                                             └─▶ 파형 (0.1초 단위 최대 진폭)   │
│                                                                           │
│  SwiftData: Meeting · Utterance · Bookmark · Summary · ActionItem          │
│             Conversation · ChatRecord                                     │
│                                                                           │
│  EventKit (미리알림) ◀─▶ ReminderService (등록, 완료 양방향 동기화)          │
└───────────────────────────────┬───────────────────────────────────────────┘
                                │ HTTPS, 앱 토큰 (텍스트만, 음성은 보내지 않음)
                                ▼
                 ┌────────── 중계 서버 (Node 22) ──────────┐
                 │ /v1/summarize   /v1/ask                 │
                 │ 인증 · 기기별 횟수 제한 · 입력 검증       │
                 │ 구조화 출력 검증 · 회의 본문 로그 안 남김   │
                 └──────────────────┬──────────────────────┘
                                    ▼
                          Claude API (Haiku 5.5, 교체 가능)
```

API 키는 서버 환경 변수에만 있다. 앱에는 이 중계 서버 전용 토큰만 들어간다.

## 화면

| 탭 | 역할 |
|---|---|
| 질문 (첫 화면) | 지난 회의에 대한 채팅. 답변 아래 근거 카드 → 해당 회의의 그 발언으로 이동·강조. 대화 기록 저장. 입력창 옆 녹음 버튼 |
| 회의 | 회의 목록·검색(제목·요약·대화). 상세: 파형 타임라인, 말풍선 대화, 구간 재생, 요약 카드(편집·다시 요약·미리알림), TXT 내보내기 |
| 할 일 | 모든 회의의 할 일. 밀어서 완료/미리알림, 길게 눌러 수정, 완료됨 섹션 |
| 내 정보 | 로그인·메일 연동 자리(준비 중), 저장 공간, 개인정보 안내 |

녹음 흐름: 동의 화면(매번) → 권한 확인 → 녹음(실시간 말풍선, 파형, 중요 표시 버튼) → 종료 확인 → 상세(자동 요약).

## 주요 흐름

### 1. 녹음과 받아쓰기
- `TranscriptionService`가 `AVAudioEngine` 입력 탭에서 버퍼를 받아 `AudioPipeline`으로 넘긴다.
- `AudioPipeline`(오디오 스레드)은 버퍼를 인식기 형식(`SpeechAnalyzer.bestAvailableAudioFormat`)으로 변환한 뒤,
  **같은 버퍼**를 ① `SpeechAnalyzer` 입력 스트림 ② m4a 파일 ③ 파형 계산에 쓴다.
  같은 버퍼를 쓰기 때문에 인식 결과의 시간 구간이 음성 파일의 재생 위치와 정확히 맞는다.
- `SpeechTranscriber`가 확정한 결과(문장 단위, `audioTimeRange` 포함)마다 `Utterance`로 즉시 저장한다.
  앱이 강제 종료돼도 마지막으로 확정된 문장까지 남는다.
- 입력 장치 변경(이어폰)·전화 중단 시 엔진을 다시 연결한다. 변환기는 입력 형식이 바뀌면 새로 만든다.
- 중요 표시(`Bookmark`)는 벽시계가 아니라 **녹음된 음성 길이** 기준 시각으로 저장한다.

### 2. 요약
- 녹음 종료 → 받아쓴 글자가 공백 제외 30자 이상이면 `MeetingSummarizer`가 자동으로 요청한다.
- 요청에는 발화(시각 포함)와 중요 표시 시각이 들어간다. 서버는 JSON 스키마 구조화 출력으로
  `{topic, summary, decisions[], action_items[{task, owner|null, due|null}], open_questions[]}`를 받는다.
- 상태 전이: `recording → processing → ready | failed`. 형식 오류만 1회 재요청. 실패해도 원문은 남는다.
  앱이 요약 도중 종료되면 다음 실행 때 `processing`을 `failed`로 바꿔 다시 시도할 수 있게 한다.
- 편집은 `SummaryDraft` 사본을 고친 뒤 저장할 때만 반영한다 (취소 가능, 미리알림 연결 유지).

### 3. 질문 (AI 채팅)
- `AskContextBuilder`가 질문 낱말로 회의를 점수화(제목 3·요약 2·대화 1)해 6만 자 한도까지 담는다.
  맞는 회의가 없으면 최근순. 긴 회의는 낱말이 나온 발화와 앞뒤 2개만 보낸다. 나머지 회의는 제목·날짜·주제 목록만.
- 발화마다 `m1-u3` 같은 번호를 붙여 보내고, Claude는 **번호로만** 근거를 댄다.
  서버와 앱이 각각 요청에 없던 번호를 버리므로 근거 카드에는 실제로 녹음된 발화만 나온다.
- 대화는 `Conversation`/`ChatRecord`로 저장. 최근 6턴을 함께 보내 이어서 묻기를 지원한다.
- 맥 에이전트(D28·D30·D34): 입력창은 하나다. `AgentHTTPClient`가 tailnet HTTPS로 사용자의 맥(local-ai-agent API v2)에 연결한다.
  모든 메시지는 먼저 맥의 대화 담당(`POST /v1/messages`, 회의 발췌 8000자 + 바로 앞 Claude 질문·답)에게 간다. 맥이 정한 대로
  답을 보여 주거나, 선택지 버튼으로 되묻거나, 작업으로 넘기거나, 회의 질문이면 위의 Claude 경로로 보내고 "Claude 사용"을 붙인다.
  작업은 상태를 조회하다 승인 대기면 승인 카드를 띄우고, 화면에 보인 초안의 해시와 함께 승인한다(D32). 진행 중인 작업도 저장해 돌아오면 이어서 확인한다(D33).
  맥에 연결할 수 없으면 회의 질문만 답한다. 주소·토큰이 설정되지 않으면 예전처럼 Claude 경로만 쓴다. 개발용 가짜는 `MockAgentClient`.
  채팅에는 확인 문장·작업 카드·결정할 일(승인, 질문)·결과만 보이고, 세부 단계 기록과 맥이 이해한 내용은 `AgentTaskDetailView`에 있다.
  작업 도중의 질문(D39): 맥이 묻고 멈추면 질문 카드를 띄우고, 고른 답이나 입력창에 쓴 글을 `POST /v1/tasks/{id}/answer`로 보낸다. 같은 작업이 이어진다.
  새 기능은 맥의 `GET /v1/health`가 알려 주는 `features`에 있을 때만 쓴다 (버전 헤더, 메시지 번호). 진행 기록은 맥이 쓴 진행 설명을, 결과는 "한 일 / 하지 못한 일" 보고를 보여 준다.
  답을 받지 못한 메시지는 같은 번호(`client_message_id`)로 다시 받아 작업이 두 번 만들어지지 않게 한다(D40). 앱이 뒤로 가면 진행 중인 요청은 약 30초 더 받고, 돌아오면 따라잡는다(D41). 앱이 닫힌 동안의 알림은 없다.
  답변 말투(내 정보 > 대화)는 맥에는 `tone`(기능 목록에 있을 때만), Claude 프록시에는 `/v1/ask`의 `tone`으로 보낸다. 답하는 말만 바뀌고 판단·작업·초안은 같다(D42).
  다음 단계(D31): 본인 주소 발송, 연락처. 서버 쪽 구현 이후.

### 4. 미리알림
- `ReminderService`가 `ReminderStore` 프로토콜(실제: EventKit)을 통해 등록·완료·동기화한다.
- 기한 문구("금요일", "다음 주 화요일")는 `DueDateSuggester`가 날짜로 바꾼 **제안**을 보여 주고,
  사용자가 켠 경우에만 날짜를 넣는다 (종일 일정).
- 완료 상태는 양방향: 앱에서 완료 → 미리알림 완료. 미리알림 앱에서 완료·삭제 → 할 일 탭을 열 때 반영.
